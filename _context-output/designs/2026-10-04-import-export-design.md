## 1. Overview

### 1.1 为何迭代

现有导入/导出实现有 4 项缺陷，其中 2 项**静默损坏用户数据**：

| # | 发现 | 证据 |
|---|---|---|
| F1 | 设计要求的「逐槽位冲突表」未接线，设置页只有两个单选按钮 | `ImportPreviewTable` 完整存在但**全仓无引用**（仅 `vite.config.ts:36` 打进入口） |
| F2 | **「Keep existing (merge)」名不副实，且静默丢弃全部规则** | `commitImport` 中 `state.rules = preview.rules` 无条件整体替换 |
| F3 | 本地图标导出为 `[local:xxx]` 占位，界面全程不提示 | `import-export.service.ts:49`；设计要求提示（`constraints-…-privacy-design.md:41`） |
| F4 | 导入路径的并发保护形同虚设 | UI 不带 `configVersion` → 后端取当前版本 → 乐观锁必然通过 |

### 1.2 使命与判据

> 把导入/导出从"两个单选按钮 + 静默整体替换"改造成**一个自描述可携带包**，其导入过程**可解释、可保真**、且由**按维度显式选择的模式**决定边界，并让"分享单条规则/槽位"与"全量迁移"走同一套语义。

**两条硬指标（取舍顺序 `B > A`）**

| 判据 | 定义 | 所堵缺陷 |
|---|---|---|
| **A. 保真** | 全量包 导出→导入 等价无损；任一导入路径不得改动用户未勾选的记录，须有测试证明 | F2 |
| **B. 可解释** | 导入前展示**每条记录将发生什么**（+ 原因），且与提交结果**逐条一致**（预览是合同） | F3 |

> **可逆（原第三条硬指标）已撤回** —— 用户裁定「不需要实现导入撤销」。替代保障为"量化后果 + 可选备份 + 风险确认"。
> **不背兼容**（开发阶段）→ 三处宽容读取（legacy 判别 / 静默纠正 / 可选字段）全部收紧。

## 2. 传送模型：可携带包

### 2.1 形状

**同一个 schema，全量与子集同构** —— 导出可勾选范围（全部 / 某维度 / 某记录），导入按"文件里有什么就合并什么"处理。

```
{
  schemaVersion,               // 校验用
  generator,                   // 扩展名 + 版本；仅诊断，不参与校验
  exportedAt,
  scope,
  slots?,                      // 显式的可携带记录（已剥离 strategy）
  rules?,
  settings?                    // 策略：全局三项 + 每 slot 的 strategy
  shortcuts?                   // 新增维度：全局 1 + 每 slot 20 个命令
}
```

**独立传输 schema + 双向映射层**（`SyncState ⇄ 包`），**不镜像内部形态** —— 因为导出时图标已被改写，且镜像会让 `createdAt` / `updatedAt` / `configVersion` 等内部字段泄漏进文件（在 C8 下还须被逐项披露为"未知字段"）。

### 2.2 维度集合（恰好覆盖 `SyncState` 全部字段）

| # | 维度 | 承载内容 |
|---|---|---|
| 1 | 槽位 | 10 个 `SlotDefinition`（**剥离 `strategy`**） |
| 2 | 规则 | `PageRule[]` |
| 3 | 策略 | 全局三项 + 每 slot 的 `strategy` |
| 4 | 快捷键 | 全局 1 + 每 slot 20 个命令 |

**不进包**：`bindings` / `tabOverrides` / `siteSnapshot` / `iconCache` / `diagnostics`（本地与设备语义）；`configVersion`（内部一致性标记，跨机无意义）。

### 2.3 三态由 JSON 自身表达

| 文件中的形态 | 含义 | UI |
|---|---|---|
| 字段**不存在** | 维度**未携带** | 标注"本包未包含规则"，**不提供**模式选择（按增量） |
| `[]` | 已携带但为空 | 正常，**提供**模式选择 |
| `[...]` | 已携带有记录 | 正常，**提供**模式选择 |

> 非数组维度（`settings` 对象 / `switchDirection` 枚举 / `autoBindGlobal` 布尔）只有**两态**。

### 2.4 图标承载：包内禁原始位图

| 类型 | 承载形态 | 导入方行为 |
|---|---|---|
| `Icon URL` | 纯字符串 | 直接可用；缓存由接收方自行建立 |
| 上传类 | `local-icon:` **裸引用** | 解析必然失败 → 显式占位 + 修复入口 + 清单告知 |
| Custom Icon | **可复现配方**（背景色 / 文本或 Emoji / 文本色） | 渲染时还原（分辨率无关） |

**两条硬要求**

1. **导出必须解引用并裸发引用** —— 现网 `[local:…]` 包装产出的 `[local:local-icon:icon:slot-3]` **必然无法解析**（首尾均不匹配 `startsWith('local-icon:')`）。
2. **"缺失"由消费方判定** —— 引用无法解析 ⇒ 视为缺失 ⇒ 显示占位（而非当字面值渲染）。

**配方持久化（新增能力）**：今日 `Custom Icon` 的配置**随写随丢**（一律先 `renderIconToDataUri` 再写 `{type:'upload'}`），`IconSource.type:'template'` **从未被产出过**。配方只存存储层、链路侧仍只见 data URI（复用 `iconResolutionCache` 记忆化）→ **链路值模型零改动**。

> **渲染落点（2026-10-05 最终裁定 R2 —— 实施期发现 BLOCKER 后修订）**
>
> **渲染在 background，用 `OffscreenCanvas` 产出 PNG；落点 = `storage-repository.ts` 的 `resolveIconReferences`（读取时物化）。**
>
> 对 `icon.type === 'template'`：渲染 PNG 写入 `value`，**配方字段与 `type` 原样保留** ⇒ 读取后为 `{ type:'template', value:'<data:image/png;…>', backgroundColor, text, textColor }`。链路只读 `value`（**A6「链路值模型零改动」保全**），投递与 UI 同经 `getSyncState()` 取数 ⇒ **天然共用同一结果**。
>
> **为何落到这里（R1 的落点错了）**：R1 把渲染放在 `resolveForDisplay`，而它**生产调用点 = 0**（仅测试调用）→ "UI 与投递共用"从未成立：用户保存 Custom Icon 后**页面图标不生效、UI 也不显示**。根因是 `ChainResult` 只承载 `value: string|null`，**`IconSource` 在进链时就被剥离**（`field-chain.ts:113-114` `asSet('')` → `null`，故配方恒为 `null`），且渲染 async 而 `field-chain` 是同步纯函数 ⇒ **配方必须在"进链之前"物化**（这正是 A6 决策句原文「链路解析时渲染」的本意）。
>
> **落点可行的决定性事实**：`field-delivery-service.ts:197` 已是 `await this.repo.getSyncState()`（async 障碍不存在）；`resolveIconReferences` **已在做同形状的"解析时物化"**（把 `local-icon:` 引用解析为真实 data URI，现成先例）。
>
> **⚠️ 硬要求**：渲染失败的降级**必须产 PNG 占位**，`value` 中**不得出现 SVG** —— 投递侧白名单（`content/index.ts:172-181`、`apply-fields.ts:71`）拒绝 `svg+xml`，塞 SVG 会被静默丢弃。
>
> **R1 的唯一已知风险已实测排除**：真实 MV3 service worker 内 `OffscreenCanvas` 可用，**CJK 930px / emoji 3044px 彩色 651 像素**，字体与 emoji 保真度通过。
>
> **决定性的技术理由：投递路径不经过 UI。** 页面图标的真正生效由**内容脚本的导航事件**驱动，那时**没有任何 UI 页面存在**；`apply-fields.ts` 只接受字符串，且其内联的 `isSafeFavicon` **拒绝 `image/svg+xml`**。因此"UI 侧渲染"只能修好 UI 可见面，**修不好"页面图标真正生效"**，且会迫使投递侧另设渲染器 → **两个渲染器并存**。
>
> **须纠正的一处错误**：此前"background 无 canvas"指的是 `document.createElement('canvas')`；**`OffscreenCanvas` 是 MV3 service worker 可用的平台 API**（Chromium / Firefox 均可），**无需新增依赖**。Q1=B 当时被否决的归因（"需引入编码依赖"）同样不成立。
>
> **已知风险（须 spike 验证）**：service worker 内的**字体 / emoji 保真度**不确定；失败时降级为**占位**（**不得降级为 SVG** —— 会被安全闸门丢弃）。
>
> **顺带修复的既有 latent 缺陷**：`resolveForDisplay` 的 `template` 分支产出 SVG → 在页面侧被静默丢弃。今日不显形，只因 `type:'template'` 从未被产出；**一旦配方持久化就会成活**。按 R1 一并修好。
>
> **同时必须补的写入门禁适配**：三处写入门禁（`worker-orchestrator.ts:587` / `:656`、`rule-service.ts:96`）现以 `!isSafeFaviconProtocol(favicon.value)` 判定，而配方 `value` 为空串（`url-utils.ts:618` 对空串返回 `false`）→ **配方会被误拒**。须改为排除 `type:'template'`。安全性等价：配方 `value` 从不直接进 `link.href`。

> 因包内无位图：**无需体积上限、无需 opt-in 开关**，`MAX_OUTPUT_SIZE`（声明但从未执行）的欠账**不再需要偿还**。

## 3. Architecture

### 3.1 三个动作，仅 APPLY 写入

| 动作 | 语义 | 写入 |
|---|---|---|
| `EXPORT_PACKAGE(scope)` | 按范围产出包（**也是「导出备份」的实现**） | 否 |
| `IMPORT_INSPECT(file)` | 解析 + 与现状比对 → diff。**只读、意图无关** | 否 |
| `IMPORT_APPLY(file, intent)` | 依意图应用 | **是（唯一）** |

**关键性质**：`INSPECT` 是「文件」的纯函数 → 改意图**无需重新 inspect**，UI 只需重渲染 → 也使"**UI 复用同一份字符串**"成为可能（见 §3.4）。

### 3.2 导入边界：按维度显式选择的模式

| 情形 | 增量导入（**默认**） | 覆盖导入 |
|---|---|---|
| **文件缺失、目标机有** | **保留**目标机 | **删除**目标机 |
| **文件有、目标机有** | **由 diff 决定**（默认预选覆盖） | **同左** |
| **文件有、目标机无** | 新增（**也展示在 diff**） | 新增 |

**要点**：模式**只管辖「文件缺失、目标机有」**；「双侧都有」由 diff 确认，两模式**行为相同**。因此 **"增量"不等于"不删除任何东西"**。

**逐记录可覆盖**：逐维模式是**默认值**，每行可单独改（未改动者继承维度模式）；组标题行提供「全部覆盖 / 全部保留」批量手段。

> 此设计**恰好落在既有设计之内**（`detail-ui-validation-design.md:58` 要求"逐项选择"+"一键全选"），**无需修订 ADR**。

### 3.3 提交权威在服务端

UI 只回传**用户意图**（各维度模式 + 稀疏的记录级覆盖 + 是否声明清空）；服务端**重新解析并重算 diff**，与预览比对，不一致则拒绝。**preview 仅用于展示**。

**理由**：既有实现把整个 preview 由 UI 回传，代码注释自证其风险（"may have been built by hand or mutated"）。**权威不能交给客户端**，否则判据 B 退化为礼貌性提示；且今日 UI 原样回传 `preview` 等于允许**绕过"清空需显式勾选"**（该意图在传输中根本不携带）。

**不采用"服务端缓存预览(token)"** —— MV3 下 service worker 随时可能被挂起，内存状态会丢（既有 `pendingUndo` 正因此采用惰性 `expiresAt`）。

### 3.4 预览即合同：构造性保证

**UI 复用 `INSPECT` 时读到的那一份字符串**传给 `APPLY` → 预览内容与写入内容**在构造上同一** → 无需比对、无需指纹、无需重读，**漂移不可能发生**。

> 这比"放弃检测漂移"更强：判据 B 从"通常成立"升为**结构保证**。
> （`File` 对象**不缓存内容**，故"保留 `File` 引用再读一次"无实际保护，已否决。）

### 3.5 原子性

**严格原子**：预检全部通过才允许提交；提交是**单次配置写入**；任一硬约束不满足 → **整体拒绝、配置零改动** + 定位原因 + 化解建议。

**F4 并入**：原子提交必须在**预览时确定的版本号**上执行 —— 否则"零改动"无法保证。（今日不带 `configVersion` → 乐观锁必然通过。）

**导入失败无需撤销** —— 由严格原子自动推出（失败 = 零改动 = 无物可撤）。

### 3.6 跨存储区无事务（技术现实）

`storage.sync` 与 `storage.local` **没有跨区事务**，故"清空图标键 + 写入配置"的"原子"靠**顺序 + 补偿**近似：

```
① 改/删 local 图标键  →  ② 写 sync 配置
② 失败 → 补偿：改回/恢复 local 键
```

**含义**：C3 的"零改动"须由**补偿路径**兑现；补偿**只在失败时执行**，故必须**主动注入失败**才测得到。

### 3.7 替换记录须清空其图标存储槽

引用键由**记录 id 派生**（`icon:slot-3`），slot id 恒为 `1..10` → 目标机若"恰好也有 slot 3 且其图标也曾转存"，解析会**假成功**（取到目标机自己的图标）—— **比破图更糟**（用户看到正常图标，不会去重选）。

**处置**：替换记录时**先清掉目标机该记录的本地图标键**，再写入 → 引用必然解析失败 → 稳定落入"缺失"。

**三条派生**：① 只对**真正写入**的记录执行（`keep existing` 一个字节不动）；② 与写入**同属一次原子操作**（失败即补偿）；③ ~~快照覆盖~~ **作废**（不实现撤销 → 清空为**永久删除**）。

> 此方案优于"引用键加内容哈希"：后者会迫使**迁移**，而现存 >6KB 图标**已**以 `icon:slot-N` 落库且是**唯一副本** → 改键会让用户图标**集体变缺失**（数据回归）。

### 3.8 规则 id 无碰撞（与 slot 的差异）

规则 id 为 `rule-${Date.now()}-${random}` —— **随机唯一** → 跨机导入时文件的规则**全是新增**、目标机的规则**全是缺失** → 增量模式会**同时保留两边**，可能产生**两条规则竞争同一 URL**。故需**恒定提示匹配重合**（定义见 §4.4）。

## 4. UI / 交互

### 4.1 导出

```
[维度复选框]  槽位 ▸ / 规则 ▸ / 策略 ▸（含每 slot 策略）/ 快捷键 ▸（含每 slot 命令）
              ↑ 至少勾选一个，否则禁止导出并说明原因
[导出] ──► EXPORT_PACKAGE(scope) ──► 先展示包摘要 ──► 下载
```

文件名沿用现状：`tab-bookmarks-config-YYYY-MM-DD.json`。

### 4.2 导入

**单页，维度选择器折叠**（默认折叠到维度级；展开到**字段级**可见"标题：A → B""图标：不变"）：

```
选文件 ──► IMPORT_INSPECT(file)
              └─► diff（按维度分组；组标题行带模式选择器）
                   + 各维度是否携带 + 宽容项 + 域违规项 + 匹配重合
                        ▼
   用户：选维度模式（默认增量）／逐记录改（默认覆盖）
                        ▼
                   点击「应用」
                        ▼
        确认弹窗（恒定出现）
          ├─ "将删除 3 个槽位、9 条规则，且不可撤销"
          ├─ [导出备份]                （可选，不构成前置条件）
          └─ [我了解风险，确认导入]
                        ▼
        IMPORT_APPLY(file, intent)   [复用同一份字符串]
```

**要点**

- 量化**删除**（真正不可逆），而非替换总数（替换可重做）。
- 量化须**按最终生效的选择计算**（含逐记录覆盖制造的删除），并由服务端重算后校对。
- 两个按钮是**并列选择**：点「导出备份」**不自动放行**（否则备份成为隐性必填，退回"强制备份"的缺陷）。
- 提示须说明**备份反映导出那一刻的状态**。

### 4.3 导入结果清单

| 分类 | 内容 |
|---|---|
| 成功 | 新增 / 替换 / 保留 / 跳过的逐条结果 |
| 宽容项 | 未知字段被忽略 / 可选字段被填默认（**折叠汇总 + 展开**） |
| **域违规** | **"因不安全被跳过"单独归类**（**醒目、不可跳过**） |
| **缺失图标** | "N 个图标需重新选择" + **行内修复入口** |
| **匹配重合** | "导入后存在 N 处匹配重合" |
| **快捷键** | Chrome/Edge：引导到 `chrome://extensions/shortcuts` 手动设置 |

### 4.4 匹配重合的定义

**`Match URL` + `Match Type` 完全一致**。

**边界（有意收窄）**：不覆盖**语义重合**（如 `https://a\.com/.*` 与 `https://a\.com/x` 匹配同一 URL 但字符串不同），与既有"潜在但不可判定的重叠"立场一致。

**判据**：对**最终状态**的纯函数 → 单元可测。

### 4.5 跨浏览器能力差异

| 平台 | 快捷键维度 |
|---|---|
| Firefox | 有 `commands.update()` → **自动应用** |
| Chrome / Edge | **不提供** `commands.update()` → **只读**：展示差异 + 引导手动设置；**不提供「覆盖」模式**（无法执行删除） |

**二者都不视为失败**。适配器现**只有 `getAll()`，无 update**（`chrome-adapter.ts:54-73`）→ 需新增 Firefox 能力与 Chrome/Edge 差异报告。

> **不选"Chrome/Edge 下隐藏该维度"** —— 会让包的含义依赖来源平台，与"三态由文件自身表达"相悖。
> **不选"包随平台变化"** —— "从 Chrome 迁到 Firefox"恰是最需要导出快捷键的路径（`decisions.yaml:100`）。

## 5. 数据流

```
导出
  scope 勾选 ──► EXPORT_PACKAGE(scope)
                    │ 读 SyncState（已 resolveIconReferences）
                    │ 图标改写：URL → URL ／ 上传类 → 裸引用 ／ 配方 → 配方对象
                    │ 去掉 [local:…] 包装
                    └─► 包（独立传输 schema）──► 先展示 ──► 下载

导入
  选文件 ──► IMPORT_INSPECT(file)              [只读、意图无关]
                │ 解析 + 严格结构校验 + 宽容项收集 + 域约束校验
                │ 与目标机现状比对 → diff（维度级 + 字段级）
                └─► diff + 携带情况 + 宽容项 + 域违规 + 匹配重合
                        ▼
              用户选维度模式 + 逐记录覆盖
                        ▼
              [可选] 导出备份 ──► EXPORT_PACKAGE
                        ▼
              确认弹窗（量化 + 风险确认）
                        ▼
   IMPORT_APPLY(file, intent)                  [唯一写入者]
      │ ① 服务端重算 diff + 与预览比对
      │ ② 预检全部通过？（C3）── 否 ──► 整体拒绝 + 定位 + 化解建议
      │ ③ local：清空被替换记录的图标键
      │ ④ sync：单次写入（绑定预览版本号）
      └ ④ 失败 ──► 补偿回滚 local
                        ▼
              结果清单（成功 / 宽容 / 域违规 / 缺失图标 / 重合 / 快捷键引导）
```

## 6. 错误处理

| 情形 | 处置 |
|---|---|
| 结构性错误（非对象 / 缺关键数组） | **整体拒绝** |
| 版本不符（`schemaVersion`） | **严格拒绝**（C8 的宽容**不适用**） |
| 未知字段 / 缺可选字段 | **宽容读取 + 逐项披露 + 确认** |
| **域违规**（`slot.id ∉ 1..10`、`urlMatch.type` 非法、不安全正则、URL 超长） | **跳过该记录 + 醒目披露**，整体导入继续 |
| 配额不足 | **整体拒绝** + 化解建议（如"减少勾选范围"） |
| 版本冲突（`STALE_VERSION`） | **整体拒绝** |
| sync 写入失败 | **补偿回滚** local 图标键改动 |
| 上传类图标引用不可解析 | 视为**缺失** → 占位 + 修复入口 + 告知一次 |
| 文件在预览后被改动 | **不可能发生**（§3.4 构造性保证） |
| 导入本身失败 | **无需撤销**（零改动） |

### 6.1 域违规为何不整体拒绝

**技术等价性**：B4 注释明确"模式**从不被执行**，只做静态校验"（`service.ts:251`）→ 不安全正则的危害**只在于被写入**；跳过即不写入，**与整体拒绝在安全性上等价**。

**必须推导出的事实**：域违规记录**只能被丢弃**，绝不能照原样写入 —— 否则 `slot.id = 11` 会产生**看不见、改不掉的槽位**；不安全正则会进入生效规则。

**硬要求**：披露**醒目且不可跳过**，并单独归类为"因不安全被跳过"（与"未知字段被忽略"区分）。

**须一并修改的既有实现**：`findUnsafeRegex` 失败由"拒绝整包"改为"跳过该记录"（`service.ts:122` / `:184` + 既有测试）。

### 6.2 校验边界

**严格字段集合 + 域约束**

| 检查 | 不通过 |
|---|---|
| 记录是**已知字段的精确集合**；多出字段 | 宽容 + 披露 |
| 缺少**可选**字段 | 宽容 + 披露 |
| 域约束（见上） | 跳过 + 披露 |

**为何 `slot.id ∈ 1..10` 是必要的新增**：否则包里能出现 slot 11，而 UI 只有 10 行。

## 7. Testing Strategy

**分层，按"可确定性"划分**（与仓库既有 `unit / integration / ui-smoke` 同名同形）

| 层 | 覆盖 |
|---|---|
| **单元** | 包解析 / 校验 / 映射层 / diff / 意图应用 / 配方序列化 / **匹配重合检测** |
| **集成** | 跨存储顺序与**补偿路径** —— **注入 adapter 失败以强制走补偿**；原子性（零改动）；版本号绑定 |
| **手工 + `ui-smoke`** | canvas 渲染（配方）、真实浏览器行为、Chrome/Edge 快捷键引导 |

**为何必须注入失败**：自然流向只走成功路径，而**成功路径恰恰是最不需要保护的一半**。

## 8. Trade-offs

| 取舍 | 选择了 | 放弃了 | 理由 |
|---|---|---|---|
| 包形态 | 独立传输 schema + 映射层 | 省掉映射代码 | 镜像会让内部字段泄漏并迫使其被披露为"未知字段"；且"未携带"与"未改动"在文件里会长得一样 |
| 提交权威 | 服务端重算 | 客户端回传 preview（更省一次推导） | 权威交给客户端使"预览即合同"退化为礼貌性提示 |
| 预览缓存 | 不缓存（无 token） | 省一次解析 | MV3 service worker 会挂起 |
| 撤销 | **不实现** | 安全性 | 用户裁定；以"量化 + 可选备份"替代 |
| 域违规 | 跳过 + 披露 | 整体拒绝（更强的一致性） | 安全性等价（不写入即无风险），且不因一条坏记录毁掉整次导入 |
| 平台差异 | 统一 schema + 降级执行 | 平台化隐藏 | 隐藏会让包的含义依赖来源平台 |
| 配方归属 | 存储层 | 链路携带配方（更灵活） | 链路把 `value` 当文本渲染，联合类型会直接显示成对象 |
| 包内图标 | 禁位图 | 搬运字节 | 单图标可 ~2.7MB，10 槽位 ~27MB；且 URL 缓存应交由接收方建立 |
