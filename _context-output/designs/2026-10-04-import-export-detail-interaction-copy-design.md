## 0. 本层对上游决策的修订

### 0.1 增量模式的定义更正（对 A1/A4 的更正）

**初稿的错误简化**：把"文件有、目标机有 → 以文件为准"当作**通则**。

**更正后的完整定义**

| 情形 | 增量导入（**默认**） | 覆盖导入 |
|---|---|---|
| **文件缺失、目标机有** | **保留**目标机 | **删除**目标机 |
| **文件有、目标机有** | **由 diff 决定**（用户确认保留/覆盖） | **同左** —— 同样由 diff 决定 |
| **文件有、目标机无** | 新增（**也展示在 diff**） | 新增 |

**要点**：模式**只管辖「文件缺失、目标机有」**这一种情形；「双侧都有」由 diff 确认，两种模式**行为相同**。

**由此推出**：**"增量"不等于"不删除任何东西"** —— 是否删除由**最终 diff 结果**决定（逐记录覆盖可把某行改为删除），不由模式名决定。

### 0.2 域违规处置放宽了 C3 与既有 B4 闸门

| | 内容 |
|---|---|
| **原 C3** | 「任一硬约束不满足（配额不足 / 版本冲突 / **记录非法**）→ 整体拒绝」 |
| **修正后** | 域违规（记录非法）→ **跳过该记录 + 披露**，**整体导入继续** |
| **既有实现** | `findUnsafeRegex` 失败 → **拒绝整个导入**（`service.ts:122` / `:184`），且有测试断言该行为 → **须一并修改** |

**技术等价性论证**：B4 的注释明确"模式**从不被执行**，只做静态校验"（`service.ts:251`），因此"不安全正则"的危害**只在于被写入**；跳过即不写入，与整体拒绝在**安全性上等价**。

**硬要求（用户确认）**：**披露必须醒目且不可跳过** —— 不安全正则属**安全类**，静默跳过比拒绝更危险，须在结果清单里单独归类为"因不安全被跳过"，与"未知字段被忽略"**区分开**。

## 1. 决策记录

### D1 — 导出范围勾选的界面组织

**决策**：**维度为主、记录为展开** —— 每个维度一个复选框（勾"槽位" = 全选 10 个），可展开到单个记录后取消个别；「策略」与「快捷键」同为维度。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 记录平铺清单 | 把维度降级为视觉分组，与导入侧"维度是决策单元"不匹配 |
| 预设按钮 + 记录微调 | 引入第二套入口表达同一件事；"导出全部"用维度勾选只需一次操作 |

**派生（用户确认）**：**空选择必须被拦下** —— 一个维度都不勾时**禁止导出**并说明原因（否则产出一份"什么都不含"的包，导入时按 D5/A2 完全无效果，用户会以为坏了）。

> 注意「仅策略」/「仅快捷键」是**合法**组合 → 规则是"**至少一个维度被勾选**"，而非"必须有记录"。

---

### D2 — 维度扩展

**决策**（用户原话）：「策略」维度需支持**每个 slot 的数据**导出导入；**Shortcuts 也需支持导出导入**。

---

### D3 — `strategy` 唯一归属策略维度；Shortcuts 同构

**决策**：**`strategy` 归策略维度** —— 槽位维度的可携带记录**剥离 `strategy`**（唯一归属）；**Shortcuts 的导出导入规则与 strategy 一致**。

| 维度 | 全局项 | 逐 slot 项 | 唯一归属 |
|---|---|---|---|
| **策略** | `matchSettings` / `switchDirection` / `autoBindGlobal` | 每 slot 的 `strategy` | 槽位维度**剥离** `strategy` |
| **快捷键** | 第 21 个命令（"下一个匹配页"） | 20 个 slot 命令 | 槽位维度**不承载**快捷键 |

**为何必须唯一归属**：`strategy` 是 `SlotDefinition` 的字段 → 若槽位维度也带它，则"取消勾选 slot 3、但勾选策略→slot 3"会使"该字段算不算被携带"变成**两个复选框的并集**，而 **C4 要求「文件 + 意图」可重算** —— 并集无法表达。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 归槽位维度（策略维度只含全局） | **做不到用户的要求** —— "只勾策略维度"将无法导出任何 per-slot 策略 |
| 允许重叠（出现即并集） | 文件含义变成并集，**C4 的服务端重算失去确定性** |

**派生**：单独导出槽位时**不含** per-slot 策略与快捷键，导入方保留自己的（与 A1「缺失即增量」一致）。**须在预览里写成显式行项**（"slot 3 策略：未携带 → 保留目标机"），避免用户意外。

---

### D4 — 跨浏览器能力差异的处置

**决策**：**统一 schema，按平台能力降级执行** —— 包内**始终**包含 Shortcuts；导入时按平台决定行为：Firefox **自动应用**，Chrome/Edge **展示差异 + 引导手动设置**；二者**都不视为失败**。

**事实依据**

| | 事实 |
|---|---|
| 适配器 | **只有 `getAll()`，没有 update**（`chrome-adapter.ts:54-73`） |
| Chrome / Edge | **不提供** `commands.update()` —— 快捷键须由用户在 `chrome://extensions/shortcuts` **手动设置** |
| Firefox | **有** `browser.commands.update()` |

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| Chrome/Edge 下隐藏该维度 | 使包的含义依赖来源平台（同一份包在 Firefox 4 个维度、在 Chrome 3 个），与 A3「三态由文件自身表达」相悖 |
| 包随平台变化（仅 Firefox 携带） | **摧毁该特性的主要用途** —— "从 Chrome 迁到 Firefox"正是最需要导出快捷键的路径，而 `decisions.yaml:100` 明确"导入/导出"的存在理由就是覆盖跨浏览器迁移 |

**两条派生（用户确认）**

1. **Chrome/Edge 下该维度不提供「覆盖」模式**（无法执行删除），UI 须说明原因，而非给出一个点了没反应的开关（A2 同一原则）。
2. **"引导手动设置"必须进入预览/结果清单**（"slot 3 快捷键：`Ctrl+Shift+1` → `Alt+1`，请到 `chrome://extensions/shortcuts` 手动设置"），否则判据 B 在该平台失效。

---

### D5 — 维度集合（核对闸门）

**决策**：**就是这 4 个，不再增删**

| # | 维度 | 承载内容 |
|---|---|---|
| 1 | **槽位** | 10 个 `SlotDefinition`（**已剥离 `strategy`**） |
| 2 | **规则** | `PageRule[]` |
| 3 | **策略** | 全局三项 + 每 slot 的 `strategy` |
| 4 | **快捷键** | 全局 1 + 每 slot 20 个命令 |

**覆盖性论证**：这 4 个恰好覆盖 `SyncState` 的**全部**字段（`slots` / `rules` / `matchSettings` / `switchDirection` / `autoBindGlobal` + 已剥离的 `strategy` + 浏览器托管的快捷键），**无遗漏、无重复**。

**已核查、确认不进包的**（本地/设备语义，此前已裁定）：`bindings`、`tabOverrides`、`siteSnapshot`、`iconCache`、`diagnostics`。

**`configVersion` 不随包**：它是**内部一致性标记**（表达"这是第几版"），非用户资产、跨机无意义；导入后由目标机自行递增（C3 已绑定版本号，递增由 `writeSync` 完成）。

---

### D6 — 导入交互的整体形态

**决策**：**单页，但维度选择器折叠** —— 预览表为主体（已按维度分组）；每组的模式选择器放在**组标题行**上；破坏性提示与按钮固定在底部。

**默认折叠层级**：**折叠到维度级**（只看到 4 行 + 模式选择器），需要时展开单条记录 —— 与 `MaskedSummary` 的既有手法一致，避免"10 槽位 + 9 规则"一上来就 19 行。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 单页平铺 | 维度选择器、diff、量化提示、两按钮平铺时需滚动才能看到破坏性提示 —— 而提示与按钮**必须同时可见** |
| 两步向导 | 第 1 步选模式时看不到"会删掉什么"，正是判据 B 要消灭的形态；且浪费 A11 的"改意图不需重新 INSPECT" |

---

### D7 — 破坏性提示的时机与形态

**决策**（用户原话）：**仅在 diff 完成点击「应用」后，恒定展示确认弹窗**

```
diff 界面 ──点击「应用」──► 确认弹窗（恒定出现）
                              ├─ 量化提示："将删除 3 个槽位、9 条规则，且不可撤销"
                              ├─ [导出备份]
                              └─ [我了解风险，确认导入]
```

**取代**：先前的"底部常驻提示行"与"仅在有删除时出现（按规模分级）"。

**量化语义**：量化**删除**（真正不可逆），而非替换总数（替换可重做 —— 文件还在，再导一次即可）。数字夸大反而不被信任。

**派生**：量化必须**按最终生效的选择计算**（含逐记录覆盖制造的删除），并在提交前**由服务端重算后校对**（与 C4 一致）。

---

### D8 — 「双侧都有」行的默认裁决

**决策**：**预选「覆盖」（文件胜出）** —— 导入即采用文件值；要保留目标机需用户主动改。

**为何默认覆盖是安全的**（推翻我此前的推荐理由）：我原担心"没看就点会静默改配"，但 **D7 的恒定确认弹窗**恰好消解它 —— 用户在弹窗里会看到"将替换 M 条"，所以默认覆盖**不是静默的**；且该语义更符合"导入 = 把文件内容都应用上，不碰文件没提的"，**可预测性更强**。

**派生**：组标题行需提供「全部覆盖 / 全部保留」批量手段（即 A4 的逐维默认充当快捷方式），否则逐条改会点到手酸。

---

### D9 — 缺失图标的呈现与修复入口

**决策**：**显式占位（灰色 `?`）+ 行内"需重新选择"标注 + 直接修复入口** —— 占位旁给出「重新选择图标」按钮，直接打开该槽位的图标编辑器。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 走既有回退（`🔖`） | 使"缺失"与"本来没有"**无法区分** —— 用户看一个 `🔖` 无法判断"设了没生效"还是"从来没设过"，而 C9 已确定"缺失"是**有意义的持续状态** |
| 显式占位但无修复入口 | C9 的告知是**一次性清单**；用户关掉后要修复得自己回想"是哪个槽位、去哪改" |

**复用**：`icon-service.getPlaceholder()`（灰色 `?` SVG）与既有图标编辑器，不新增组件。

### D10 — 规则匹配重合的提示

**决策**：**恒定提示** —— 无论模式，只要**最终结果里存在重合**就提示。

**"匹配重合"定义（用户给出）**：**`Match URL` + `Match Type` 完全一致**。

**事实依据（为何规则维度需要它）**

```
142:142:src/background/rule-service.ts
    id: `rule-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`,
```

规则 id **随机唯一**（不像 slot id 恒为 `1..10`）→ 跨机导入时文件的规则**全是"新增"**，目标机的规则**全是"文件缺失"** → **增量模式会同时保留两边**，可能产生**两条规则竞争同一 URL**（由优先级决胜负），用户会看到"导入后某些 URL 有两条规则"却不知为何。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 不提示 | 把"可解释"缺口留给用户发现；而"多了一条竞争规则"**改变运行时行为**，影响大于"标题从 A 变成 B" |
| 仅在可能产生重合的模式下提示 | 逻辑有漏洞 —— 重合也可来自**包内部**（文件本就有两条匹配同 URL 的规则），那时与模式无关 |
| 恒定提示（本项） | 判据最简单最可靠："**最终结果里是否存在重合**"，天然覆盖三种来源（模式保留+新增、文件内部重复、逐记录覆盖组合） |

**性质**：重合检测是**对最终状态的纯函数**，单元可测（属 A13 的纯逻辑层）。

**边界（有意收窄）**：该定义**不覆盖语义重合** —— 如 `https://a\.com/.*` 与 `https://a\.com/x` 都能匹配同一 URL 但字符串不同。与既有"潜在但不可判定的重叠"立场一致。

### D11 — 契约一：包的身份与可扩展性

**决策**：**`schemaVersion` + `generator`（扩展名 + 版本）** —— `generator` **仅作诊断信息**（出问题时可判断包由哪个版本产出），**不参与校验**。

**理由**：`generatePreview` 的拒绝信息目前**无法定位"是什么工具、什么版本产出的"**，而"包被谁写的"恰是排查导入失败时最先要问的问题；成本仅两个字段，且不参与校验（不会使某些包被误拒）。

---

### D12 — 文件内容如何抵达 APPLY（关闭 A5）

**决策**：**UI 复用 `INSPECT` 时读到的同一份字符串** —— 预览与写入**同源**；无需比对、无需指纹、无需重读。

**为何比 A5 的"不比对"更强**：A5 是"**放弃检测漂移**"，本项是"**让漂移不存在**" —— 预览内容与写入内容在**构造上同一**。判据 B（预览即合同）由此从"通常成立"升为**结构保证**。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| APPLY 时重新读取磁盘文件 | 退回到需检测（A5 已否决的路子） |
| UI 保留 `File` 对象引用，APPLY 时再读 | ⚠️ `File` **不缓存内容**，再次读取仍会反映磁盘变化 → 无实际保护 |

**成本**：文件是 KB 级（C1 已定不搬运位图，包更小），留在内存无压力；反而**省掉** A5 的遗留待决项。

### D13 — 契约二：导出文件的命名

**决策**：**固定前缀 + 日期（现状）** —— `tab-bookmarks-config-YYYY-MM-DD.json`。

**说明**：同日多次导出由浏览器自动加 `(1)` 后缀，**已知可接受**（用户明确保留现状）。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 按范围命名（`tbs-rule-<id>-<date>.json`） | 用户选择保留现状 |

### D14 — 记录级校验边界

**决策**：**严格字段集合 + 域约束**

| 检查 | 不通过时的处置 |
|---|---|
| 记录是**已知字段的精确集合**；多出字段 | 走 C8 宽容 + **披露** |
| 缺少**可选**字段 | 走 C8 宽容 + **披露** |
| **域约束**：`slot.id ∈ 1..10`、`urlMatch.type ∈ {exact, regex}`、正则通过既有 B4 闸门（`findUnsafeRegex`）、URL 长度上限 | **披露**（见 D15），**不整体拒绝** |

**为何字段集合要精确检查**：A14 选的是**独立传输 schema**，其意义正是"文件里是什么"要**可枚举、可验证**；放弃字段集合检查等于把收益还回去（且"缺了必填"与"缺了可选"将无法区分）。

**为何 `slot.id ∈ 1..10` 是必要的新增**：否则包里能出现 slot 11，而 UI 只有 10 行 → 导入后产生**一条看不见、改不掉的槽位**。

**复用**：正则安全闸门（B4）与 URL 校验**已存在**，本项只是复用，不是新造。

---

### D15 — 域违规的处置

**决策**：**一律「跳过该记录 + 披露」** —— 含不安全正则在内的所有域违规，均按"**该记录视为未携带**"处理并逐项披露；**整体导入继续**。既有 B4 闸门由"拒绝整个导入"放宽为"跳过该记录"。

**必须推导出的事实**（非选择题）：域违规记录**只能被丢弃**，**绝不能照原样写入** ——

| 若写入 | 后果 |
|---|---|
| `slot.id = 11` | 写进 sync 而 UI 只有 10 行 → **看不见、改不掉的槽位** |
| 不安全正则 | 进入用户生效规则 → 引入**实际运行时风险** |

所以"披露不拒绝"的可行含义**只有一个**：**该记录跳过 + 披露**，其余记录照常导入。

**技术等价性**：见 §0.2。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| 分级（安全类仍整体拒绝） | "整包拒绝"对分享场景过重，而换来的额外安全性**为零**（跳过即不写入） |

**硬要求（用户确认）**：**披露必须醒目且不可跳过**，并单独归类为"因不安全被跳过"。

## 2. 交互全貌

### 2.1 导出

```
[维度复选框]  槽位  ▸（展开：slot 1 … slot 10）
              规则  ▸
              策略  ▸（含每 slot 的 strategy）
              快捷键 ▸（含每 slot 命令）
                  ↑ 至少勾选一个，否则禁止导出并说明原因
[导出] ──► EXPORT_PACKAGE(scope) ──► 先展示包摘要 ──► 下载 JSON
```

### 2.2 导入

```
选文件 ──► IMPORT_INSPECT(file)   [只读、意图无关]
              └─► diff（折叠到维度级；展开到字段级："标题：A → B""图标：不变"）
                   + 各维度"是否携带" + 宽容项 + 域违规项 + 匹配重合
                        │
   用户：组标题行选模式（默认增量）／逐记录改（默认覆盖）／批量全选
                        │  ⚠️ 改意图不重新 INSPECT
                        ▼
                   点击「应用」
                        ▼
        确认弹窗（恒定）
          ├─ "将删除 3 个槽位、9 条规则，且不可撤销"
          ├─ [导出备份]                （可选，不构成前置条件）
          └─ [我了解风险，确认导入]
                        ▼
        IMPORT_APPLY(file, intent)   [复用 INSPECT 读到的那一份字符串]
```

## 3. 本层结论摘要

| 编号 | 项 | 决策 |
|---|---|---|
| D1 | 导出范围组织 | 维度为主、记录为展开；**空选择禁止**（至少一个维度） |
| D2 | 维度扩展 | 策略含每 slot 数据；新增 Shortcuts 维度 |
| D3 | 字段归属 | `strategy` 唯一归策略维度；Shortcuts 同构 |
| D4 | 平台差异 | 统一 schema，按能力降级（Firefox 自动 / Chrome·Edge 引导） |
| D5 | 维度集合 | 槽位 / 规则 / 策略 / 快捷键（覆盖 SyncState 全部字段） |
| D6 | 导入形态 | 单页 + 维度选择器折叠（默认折叠到维度级） |
| D7 | 破坏性提示 | diff 后点「应用」→ **恒定确认弹窗** + 两按钮 |
| D8 | 双侧都有 | 默认**预选覆盖** |
| D9 | 缺失图标 | 显式占位 + 行内修复入口 |
| D10 | 匹配重合 | 恒定提示；定义 = Match URL + Match Type 一致 |
| D11 | 契约一 | `schemaVersion` + `generator`（仅诊断） |
| D12 | 文件传递 | 复用 INSPECT 字符串 → **构造性无漂移** |
| D13 | 契约二 | 固定前缀 + 日期 |
| D14 | 校验边界 | 严格字段集合 + 域约束 |
| D15 | 域违规 | 跳过该记录 + **醒目披露**（整体导入继续） |

**一句话**：导出侧以**维度**为第一层、记录可展开，至少勾一个维度；导入侧单页展示**折叠到维度级**的 diff（可展开到字段级），按维度选模式（默认增量、双侧默认覆盖），点「应用」后由**恒定确认弹窗**交代量化后果并提供可选备份；`APPLY` 复用同一份文件字符串，在绑定版本号上原子写入；域违规与缺失图标一律"跳过/占位 + 醒目披露"，不因一条坏记录毁掉整次导入。
