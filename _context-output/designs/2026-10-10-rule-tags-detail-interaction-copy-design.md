## 0. 本层回溯修订的上游条目

本层在推进中发现 **Architecture A3 的一句话与既有设计权威冲突**，用户裁决后需回写。

### ⚠️ 冲突卡：`tags` 是「第 5 个维度」还是「rules 的子选项」

| 事实 | 出处 |
|---|---|
| 导入导出维度**硬编码为 4 个**，注释明写为既定决定 | `types.ts:223`「The four dimensions are FIXED (D5): slots / rules / settings / shortcuts」 |
| 四处硬编码 | `ExportScope`（4 boolean）、`DimensionPresence`（4 **必填** boolean）、`ImportIntent.dimensionModes`（4 `DimensionMode`）、`ImportDimensionOutcomes`（4 outcome） |

A3 曾写「新增第 5 个维度需同步四处模型」，**未将其标识为对既有决定的推翻**。

**裁决：独立第 5 维度 `tags`。** 补偿事实：`DimensionPresence` 是必填结构 ⇒ 加字段会**逐处编译报错**，不会漏（与 `RULE_KEYS` 同类护栏）。

**含义**：`ExportScope` 新增 `tags?: boolean` 与 `excludedTagNames?: string[]`；`DimensionPresence` / `DimensionMode` / `ImportDimensionOutcomes` 各增 `tags`；维度元数据（`DIMENSION_META`）增一项；导入面板出现**独立卡片与模式选择器**。

## 1. 决策记录

### D-a — 标签管理界面的位置

**决策**：**新增顶级导航项「Tags」**——第 7 个 section，与 Slots / Global Strategy / Rules / Data Dashboard / Import-Export / Diagnostics 并列，拥有完整页面。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| B. Rules 页内可展开面板 | 删除标签的影响是**跨规则**的（C4：摘除 N 条规则上的引用），关在 Rules 页的局部容器里看不到全局视图 |
| C. 从 Rules 页打开的 Dialog | 同 B 的语义问题（模态内难以承载全局视图）；且「删除影响数」需在模态里额外陈述。**可接受次选** |
| D. 挂在 Data Dashboard 之下 | 语义错配：Dashboard 管理的是**已生效的 title/icon 覆盖**（链的结果），标签是**组织维度**，非同类对象 |

**含义**

- 导航成本：侧边导航（非底部导航）无 ≤5 硬约束；仓库已有「一个导航项内含 Tabs」先例（Import / Export）。
- **诚实登记的代价**：标签是**低频**操作（建几个后长期不动），第 7 个导航项使导航略长；换来实体定位的准确性。
- 该页须能看见**孤立标签**（C3 要求）。

---

### D-b — 就地新建标签

**决策**：**可以就地新建。** 输入框内的名字若无匹配 ⇒ 出现一行「创建标签 "xxx"」⇒ 回车即建并选中。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| B. 只能选已有 | 把一条高频路径变成三段式（离开 → 建 → 返回）；C3 的「总数不限」意味着新建是**常规动作**而非例外 |
| C. 就地新建 + 二次确认 | 多余：新建**完全可逆**（删掉即可，且 C5 已有撤销）；为可逆操作加确认会训练用户无脑点确认。真正需要确认的是**删**标签，那里已有 `Confirm` |
| D. 建后立即进入重命名 | 用户输入的名字通常就是他想用的名字；强制进入改名态反而打断 |

**含义**

- A 与 Tags 页**互补而非重复**：Tags 页面向「批量查看 / 重命名 / 删除」，就地新建面向「此刻我要给这条规则分类」。
- ⚠️ **本层更正一处自相矛盾的表述**（详见 D-f）。

---

### D-c — 标签在规则表的呈现

**决策**：**新增独立「Tags」列 + 默认收起**，由用户切换显示（同 Data Dashboard 的 URL 显示/隐藏 `⊘` 开关）。

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| A. 新增列并始终显示 | 8 个标签 × 每片约 60px 会挤掉 **URL Pattern 列**，而那是本表信息密度最高的一列 |
| B. 并入 Title 列 | **归属错误**：标签**不是标题的从属信息**（这正是 🔒 层选 B 管理界面的理由）；挂在标题下持续暗示「标题的属性」，与实体定位矛盾 |
| D. 不显示，仅作筛选依据 | **不成立**：筛选执行后用户**必须**能验证「为什么这条被选中」；看不见标签 = 筛选结果不可核对 |

**含义**

- **「默认收起」= 列本身默认不渲染**，不是「渲染但内容为空」。
- **打标反馈不依赖该列**，落在两处：Tags 页的引用计数、规则**行内编辑器**始终显示标签（编辑场景宽度压力小）⇒ 打完标签后不存在「无从确认」。
- 复用既有 `⊘` 控件先例，**不引入新交互模式**。

### D-d — 长表达式的可读性降级（O6）

**决策**：**框体自动折行增高，高度随内容增长。**

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| A. 定高 + 内部横向滚动 | 对「确认自己构建了什么」最不友好：横向滚动使表达式失去可扫读性，而扫读正是 chip 方案相对文本的**唯一优势**（G5 选 chip 即为「看见结构」） |
| C. 定高多行 + 内部纵向滚动 | 高度恒定：多数表达式 1–2 行，固定 3 行会在常见情况下空出两行 |
| D. 超阈值降级为「N 个条件」摘要 | 引入两套渲染；且**摘要会隐藏表达式结构**（看不到 AND/OR 关系）——在需要核对时恰好把结构藏了 |

**含义**

- **与 D1 分工明确**：D1 管「不崩」（实现层），本条管「可读」（呈现层），不重叠。
- **呈现层不做任何截断**：可读性完全交给「chip + 折行 + 缩进」。
- **登记的代价**：无上限增长 ⇒ 极端情况下工具栏会被推出视口。折行以**容器宽度**为界，故该后果**可见且可理解**，不是故障；不加机制纠正（与「表达式不设上限」的同一取舍）。

### D-e — 导出自洽弹窗的措辞（O10）

**决策**：**后果式措辞。**

- 补足：`补足标签：包内将包含 3 个额外的「work」「urgent」标签定义`
- 丢弃：`丢弃标签：2 条规则将丢失「work」「urgent」标签`

**被否决的替代**

| 选项 | 否决理由 |
|---|---|
| A. 陈述式（`继续导出并补足缺失的标签（共 N 个）`） | 未说出「**收件方**会多拿到 3 个标签定义」——而它影响对方机器，用户需知道自己在往别人的配置里加东西 |
| C. 极简式（`补足` / `丢弃` + 一行说明） | 两个词无法让用户预判后果，等于让他猜 |
| D. B + 默认高亮「补足」 | Enter 触发默认按钮 ⇒ **一次误触就往别人配置里多塞标签**；且该弹窗出现的场景正是用户刚做了「排除标签」的反常操作，此时不应给他「按回车继续」的顺手路径。**两个选项应等权**，与 C5「破坏性操作用 `Confirm` 而非默认按钮」一致 |

**含义**

- 措辞中的数字与名字**直接渲染 A3/A5 的集合差集**，故文案与判定**同源**，不会漂移。
- 与项目既有立场一致：把「即将发生什么」在操作前说清（`Confirm` 报数量、diff 逐字段展示）。

### D-f — 就地新建与会话内取消的语义

**决策**：**标签立即创建并落盘；用户随后取消规则表单，标签留下（可能成为孤立标签）。**

> ⚠️ **本决策更正本层 D-b 中一处自相矛盾的表述**。初稿曾写「标签实体与引用在**同一次操作**里完成，不得出现『规则还没保存、标签已经建好』的半成品状态」。
>
> **该表述不成立**：规则表单在保存前只是本地 state（`RuleFormState`），而 `CREATE_TAG` 是一条独立的服务端写入（A1）——两者**无法**在同一笔事务里完成。补救方向只有「把创建推迟到规则保存时」，而那会让「回车即建并选中」变成**假承诺**（用户以为建好了，关掉表单就没了）。

**含义**

- 该状态**不是缺陷**，而是 C3 已接受的后果——「**孤立标签在管理界面里必须看得见**」正是为这种情形准备的（C3 含义）。
- 不引入「草稿标签」这一第三态：它会派生出「引用一个尚未落盘的标签」这类悬空，与 C7/D3 的既有处理冲突。
- **就地新建必须走同一条 `TagService` 写入路径**（A1），不得在 UI 侧自建标签对象。

## 2. 术语定稿（本迭代新增）

| 术语 | 定稿 | 说明 |
|---|---|---|
| 标签 | **tag / tags** | 实体名。中文文档用「标签」 |
| 标签表 | **tag table** | `SyncState.tags`，全局唯一的实体集合（`TagDefinition`：名字 + 双色） |
| 词汇表 | **vocabulary** | **包内**根级 `tags: PortableTag[]`（名字 + 双色，**不含 id**，A4） |
| 谓词 | **predicate** | 表达式中的单个条件，形如 `work` 或 `NOT archived` |
| 表达式 | **expression** | chip 序列构成的布尔式（G4） |
| chip | **chip** | 框内一个可单独删除的项（标签名或运算符） |
| 自洽 | **self-consistent** | 导出时「每条规则的每个名字都在根级词汇表里」（A3/A5） |

## 3. 层内自检

- **与上游一致性**：
  - G1「不影响执行」未被本层任何决策触碰（本层全部是呈现与文案）。
  - G2 的规模假设支撑 D-c（列默认收起以避免宽度问题）与 D-d（折行而非滚动）。
  - G5「无自由文本」是本层 chip 交互全部成立的前提。
  - C2「trim 逐字节相等」是 D-b 就地新建的**匹配依据**（输入的名字按此判定是否已存在）。
  - C3「孤立标签须可见」由 D-a 的独立页面 + D-f 的后果共同支撑。
  - C5 的撤销由 D-g R3 沿用串行顺序。
  - A1 的模块边界由 D-f 最后一条保证（就地新建走同一写入路径）。
  - A3/A5 的集合差集由 D-e 的文案直接渲染（同源，不漂移）。
- **矛盾检查**：
  - D-b（就地新建）vs D-f（标签会留下）——**不矛盾**：D-f 正是 D-b 的必然推论，且已作为 C3 的既有后果被接受。
  - D-c（默认收起）vs 「筛选结果须可核对」——**不矛盾**：核对靠打开列或行内编辑器，非默认可见。
  - D-d（无截断）vs 工具栏被推出视口——**已登记为接受的代价**，非矛盾。
- **本层未做**：未新增任何机制。全部决策落在**既有控件复用**（`⊘` 开关、`Confirm`、`UndoBar`、`Tabs`）与**文案**上。
- **文档冲突已回写**：`types.ts:223` 的「four dimensions are FIXED」需在实现时更新为 5 个维度（该注释是**实现期改动项**，记录于此以免遗漏）。
- **⚠️ 本层 §2 术语表的一处笔误已更正**（由规划期的文档对照质询发现）：`词汇表 / vocabulary` 一行原写「包内根级 `tags: string[]`（仅名字，A4）」，**未随 S2 回溯修订更新**——S2 已把包内根级表改为 `PortableTag[]`（仍无 id，但**携带颜色**）。该行已更正；同时把 `标签表` 一行的实体形状写明（`TagDefinition`：名字 + 双色）。这是**事实性笔误**，不涉及任何设计结论。
