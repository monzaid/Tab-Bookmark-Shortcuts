# 标签页书签快捷切换插件：架构层（MV3、数据与核心流程）

- 日期：2026-07-14
- 状态：待用户确认后进入细节层

## 运行架构

采用 Manifest V3、以 Service Worker 为中心的 WebExtensions 架构。

- Service Worker：处理 20 个保存/切换槽位命令和一个“下一个匹配标签页”命令；执行匹配、跨窗口激活、恢复会话管理、缓存与单一配置写入。
- 内容脚本：在可注入普通网页的 `document_start` 静态注入，只上报初始和 SPA 导航，接收最小标题/favicon 改写指令；不读取或上传页面正文。
- React + TypeScript 多入口 UI：扩展弹窗、设置页、恢复页、导入预览页、候选选择器，共享组件、类型、表单校验与消息客户端；UI 不直接实现浏览器业务逻辑。
- 最小 WebExtensions 适配器：封装命令、标签页、窗口、存储、页面脚本、通知和无痕访问能力，统一 Promise 行为、差异错误和浏览器兼容，不向业务代码泄漏浏览器判断。
- 跨浏览器范围：Chrome、Edge、Firefox 分别安装运行；每个浏览器实例内可跨窗口切换，不支持浏览器之间交换/切换标签页。

## 消息与错误协议

Service Worker、UI、内容脚本使用类型化请求/响应协议：共享 `action`、载荷、成功结果及领域错误码。UI 按错误码展示提示，不暴露原始浏览器错误。内容脚本仅支持导航上报与改写命令；不使用依赖常驻后台的长连接。

## 存储与一致性

### 同步持久配置（storage.sync）

保存槽位定义、精确 URL 或正则匹配定义、匹配策略、槽位 UI 标记、页面重写规则、规则优先级、全局默认策略及配置版本。

### 本地运行时状态（storage.local）

保存槽位 `tabId` 绑定、循环游标和最近成功槽位、一次性恢复会话、本地图标缓存、临时 tabId 个性化和最近恢复快照。

`storage.sync` / `storage.local` 是唯一真实来源。Service Worker 以内存缓存提高常规操作效率；启动时或缓存缺失时读取存储，并通过 `storage.onChanged` 更新/失效缓存。

所有配置写入经 Service Worker 的单写入服务，提交携带递增配置版本做乐观校验。版本不一致返回冲突错误，UI 要求刷新重试。同一设备不静默覆盖；跨设备接受浏览器同步的最后写入胜出，并在下次打开 UI 时提示外部变更。

## 匹配、循环与恢复数据流

- 精确 URL 规范化比较：忽略锚点，主机名小写，移除 HTTP/HTTPS 默认端口；路径和查询参数严格相等。
- 正则使用 JavaScript `RegExp`，最大 500 字符；编辑时校验语法、代表性 URL 试运行和风险提示。运行时每个可访问标签页 URL 至多匹配一次，始终检查全部标签页。
- 多候选排序：当前窗口优先，再按标签栏从左至右，随后其他窗口。切换槽位定位首个；“下一个匹配标签页”以最近成功切换的槽位为上下文，按本地循环游标继续。
- 失效恢复：生成随机 `recoveryId`，在本地保存槽位 ID、触发快照、创建时间和状态，恢复页仅携带 ID。会话可并存，成功、取消或 5 分钟超时后删除。恢复页实际操作时重新查询实时标签页，快照仅作原因说明；“下一个匹配页”无结果时允许点击并显示错误。
- 恢复成功：更新本地 `tabId` 与仅本地的最近恢复快照（URL、标题、favicon）；不修改原槽位精确 URL/正则匹配定义，也不导出/同步快照。

## 页面改写流程

内容脚本在初始加载、`popstate`、`hashchange` 和包装后的 `history.pushState` / `replaceState` 后报告 URL。后台以规则和 tabId 临时覆盖计算结果，再下发单次改写。

多个规则命中时，按优先级数值（-100 至 100、默认 0）降序，再按创建时间降序选择；弹窗提示实际规则及被覆盖规则。仅手动规则在用户操作后展示所有匹配页（跨窗口），由用户选择目标应用。

## 状态清理

监听 `tabs.onRemoved` 清理相应 tabId 绑定与临时个性化。创建/访问恢复会话、以及 Service Worker 启动时清理 5 分钟过期会话；启动时验证所有保存 tabId 是否仍存在，清除失效绑定。

## 通知与诊断

系统通知只用于跨窗口切换、恢复成功回绑、无目标或操作失败；同窗口普通切换和循环静默。

本地诊断日志仅记录时间、领域错误码、浏览器类型、操作类型；不含完整 URL、页面标题或规则文本。设置页支持查看、清除和手动导出；不进行遥测或上传。

## 构建、发布与验证

使用单一代码库、浏览器专属 manifest 覆盖构建 Chrome/Edge MV3 包和 Firefox 兼容包。

测试采用分层策略：单元测试验证 URL 规范化、正则校验、优先级和匹配排序；集成测试覆盖适配器、存储和消息协议；Chrome、Edge、Firefox 使用人工验收矩阵验证安装、快捷键、跨窗口、恢复、无痕授权和页面改写。
